# Taste
- Confine all work to the project directory: do not read or modify files outside the workspace (e.g. `~/.nvm/alias/default` or other global toolchain config). Get version/tooling info by running commands inside the project instead. Confidence: 0.85
- Wants least-privilege platform permissions: request only the minimum permissions required (and restrict broader access, e.g. host permissions) rather than granting everything up front. Confidence: 0.6
- Never bypass platform access controls (login walls, private accounts, authentication, download restrictions, anti-bot/security systems): surface the restriction gracefully instead of attempting workarounds. Confidence: 0.8
- Wants bounded resource usage: never fire unlimited concurrent requests; cap concurrency and respect browser resource and platform rate limits. Confidence: 0.6
- Wants honest capability reporting: only present something as available/downloadable when it genuinely is, and explicitly report unavailable cases (with a clear user-facing message) instead of assuming or fabricating support. Likewise, never claim work is correct/error-free/verified unless the relevant tests actually passed. Confidence: 0.75
- Prefers incremental, in-place changes to an existing codebase: inspect the project first, reuse the existing architecture and services, and never scaffold a new project, redesign the app, or drop working features. Confidence: 0.8
- When a capability (e.g. anonymous viewing or hiding activity) can't be done through a permitted method, mark it explicitly unavailable rather than building a workaround; never promise anonymity or concealment the tool doesn't provide. Confidence: 0.65
- Wants platform-specific logic isolated per platform (its own adapter module) and kept separate from other platforms and shared/generic code; explicitly rejects one universal/generic behavior applied across platforms (e.g. UI placement must be decided per platform and page type). Confidence: 0.75
- Before changing DOM selectors or integration points, verify against the real target: inspect the actual live DOM/structure first rather than guessing, and test the change on real supported page layouts. Confidence: 0.6
